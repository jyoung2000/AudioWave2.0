# Design decisions, exceptions and open questions

Each entry has a stable ID that `design/token-map.json`, `design/coverage.json` and the styleguide
refer to. **Adopted** means the current behaviour is the standard. **Unresolved** means the code
and the documented intent disagree and someone has to choose; until then the check records the
difference instead of failing on it, and nothing may be added to the same exception silently.

Longer histories live in [docs/DEVIATIONS.md](../docs/DEVIATIONS.md) and
[docs/AQUA_CONFORMANCE.md](../docs/AQUA_CONFORMANCE.md).

| ID      | Status     | Decision |
| ------- | ---------- | -------- |
| DEC-001 | Adopted    | Lucida Grande is not shipped (not redistributable). The window skin names it first and falls back through a tuned chain. |
| DEC-002 | Adopted    | `--aqua-font` inserts the bundled `"Aqua Fallback"` face after Lucida Grande; `tokens.json` `font.family` does not list it. The CSS is authoritative. |
| DEC-003 | Adopted    | The window skin (hub admin, Windows companion) has no dark palette, because Snow Leopard had none. The page skin (player) and the styleguide follow the system colour scheme. |
| DEC-005 | Unresolved | Discord `noResults` renders `No results for “{{reason}}”`, but the command service passes the search text as `title` and `No results` as `reason`, so the bot says “No results for “No results”.” Proposed fix: the template uses `{{title}}`. Changing a default template changes what existing servers see. |
| DEC-006 | Adopted    | Cover Flow is not implemented; the 3D jewel-case stage stands in for it. |
| DEC-007 | Adopted    | The player replaces the inset LCD display with the hero, which states the same information at reading size. |
| DEC-008 | Unresolved | The public share page (`docker-container/src/api/routes/shares.ts`) is standalone HTML under a strict CSP with its own inline stylesheet. It uses a 12px pill button and weight 600, which the system otherwise forbids. Proposed: restyle it with the page-skin values (4px push button, weights 400/700). |
| DEC-009 | Adopted    | The mockups render each product's real components with fixture data; they are not the product view files executed verbatim. Runtime coverage says which surfaces were seen in the running product and which only in a mockup. |
| DEC-010 | Adopted    | Android notifications, the document picker and the save dialog are system UI. The guide documents their copy (`strings.xml`) and when they appear, not their appearance. |
| DEC-011 | Proposed   | `tokens.json` is mirrored into the stylesheets by hand; `pnpm styleguide:check` compares the two through `design/token-map.json`. Proposed: generate the custom properties from `tokens.json` so the map becomes unnecessary. |
| DEC-012 | Unresolved | The Android shell only reaches hubs over https (mixed content is never allowed and the manifest forbids cleartext), but the player's pairing form still accepts an `http://` address, so the refusal happens at connection time. Proposed: say so in the pairing form on Android. |
| DEC-013 | Adopted    | The Windows companion is Electron-only; its renderer cannot run in a browser without the preload bridge, so its runtime evidence comes from its DOM tests and the mockups. |
| DEC-014 | Adopted    | The equalizer window (`.eqw`) has an intrinsic width: `max-width: 600px`, which holds its rails about 36 px apart the way the iTunes window does. It had been stretching to whatever container held it — 958 px in the styleguide — and read as a strip rather than a window. |
| DEC-015 | Adopted    | The note in every app icon is placed by centring the path's measured box (x 4.4–19.8, y 3–21.7 of its 24-unit grid) on the icon's optical target: the tile centre for the player and maskable icons, the folder mouth (240, 308) for the companion, the 32-square for the tray. The player icon had shipped 27 px left of centre; `tests/unit/icon-glyphs.test.ts` now pins all four placements. |
| DEC-016 | Adopted    | Play sits on the progress rail's centre line at every width, with previous and next on its line either side. `KeyTransport` measures its row: the volume line stays beside the keys only while it fits on both sides (otherwise it goes beneath, centred), and the keys wrap only when they do not fit on one line, with previous, play and next alone on the first line. The player's eleven keys never leave room for the volume beside them inside the 820 px hero, so the player shows it beneath at every width. Covered by `tests/dom/page-chrome.test.tsx`. |
| DEC-017 | Adopted    | The hub admin GUI is the six-tab window of `design/frontends/airwave-hub.html` (Overview, Devices, Music, Groups, Sharing, System); the thirteen sections keep their data flows and ledger entries and stack inside those tabs, and `#section-id` in the address still opens the right one. Two departures from that mockup stand. The first-run gate is a screen, not a banner over a disabled interface: the server refuses every gated route until the password is changed, so a live-looking interface behind the banner would be a picture of one. And the invite table shows who an invite is for and its state, not its code, because the hub keeps only a code's hash; the code appears once, when made, and the link needs the address players open Now Playing at. The mockup's `warning` (#d99a1e) yields to the existing `--aqua-warning`; its header and gate colours joined `tokens.json` as `header*` and `warningBg`/`warningEdge`. |
| DEC-018 | Adopted    | The Windows companion is the four-tab window of `design/frontends/airwave-companion.html` (Library, Live TV, Remote, Settings), on the shared `ToolTabs` strip. Live TV shows no channels: the repository keeps no M3U or EPG data, so the tab says what is missing in the mockup's amber voice rather than listing samples. The mockup's Remote tab pairs *devices to this PC* with a code; that is the AWSP streaming server's pairing (Phase 4) and arrives with it — until then Remote holds the hub connection and transfers. A backup is a dated folder (`data.json` + copied folders), measured with `local-helper/src/measure.ts` so the helper route and this window report one number; sizes are decimal units as the player shows them. |
| DEC-019 | Adopted    | The player's interface is the Airwave frontend served as the shell (shape (a) of the master prompt): `music-player/index.html` is generated from `design/frontends/airwave-now-playing.html` by `music-player/scripts/make-shell.py`, every edit asserted against the text it replaces, and `src/shell/bridge.ts` stands behind the file's seams with `db.ts`, `library.ts`, `PlaybackEngine`, `HubClient` and bundled three.js. Chosen because the edits that make playback real touch one transport block and one boot block, and the file's twenty-one suites come with it. What the shell no longer contains: the sixteen invented rows, the generated Statistics year, the demo history, the invented TV catalogue, the base64 clips, the two invented albums (now "Nothing playing" / "No group session"), and the direct call to api.anthropic.com (a third-party account). The React interface under `music-player/src/{App,views,components}` is no longer served; its logic layer (`src/lib`, `src/state`) is what the bridge uses. Back Up Now in the player measures and says nothing was sent: no route lets one machine start a backup on another. |
| NPD-001 | Adopted    | `design/frontends/airwave-now-playing.html` (served here as `music-player/index.html`) owns every token. The product is one file and its `:root` custom properties already are the token system, so no second source was introduced. `design/tokens.json` is generated from it for other consumers. (AudioWave records the opposite arrangement as its DEC-011 proposal; when this UI moves there, its tokens join `packages/aqua-ui/src/styles/tokens.json`.) |
| NPD-002 | Adopted    | The dark palette is written twice — inside `prefers-color-scheme: dark` for Auto and under `:root[data-theme="dark"]` for forced Dark — because a forced choice must beat the OS in both directions. `styleguide:check` fails if the two lists differ. |
| NPD-003 | Adopted    | Dark appearance is not period-accurate (none of the referenced releases had one). It is kept because the product follows the system scheme; each dark value is a darkened reading of the same material, never a new hue. |
| NPD-004 | Adopted    | Lucida Grande and Helvetica Neue are not shipped (not redistributable). Lists, menus and Preferences name Lucida Grande first and fall back to Lucida Sans Unicode, Segoe UI, then the system face; the status bar and Now Playing text use the system UI face as the iPhone did. Captures in this guide were rendered on Linux, where the fallback is DejaVu Sans; on macOS and Windows the named faces render. |
| NPD-005 | Adopted    | The 3D jewel-case stage loads three.js from cdn.jsdelivr.net. Without network it shows its flat fallback cover, which is what the guide's captures show. |
| NPD-006 | Adopted    | `main.demo` (the explanatory page under the player) is scaffolding for this standalone file and is removed when the header is dropped into AudioWave. It is excluded from coverage. |
| NPD-007 | Unresolved | Search placeholder `--field-hint` on the field measures 2.3:1 light / 3.8:1 dark, under 4.5:1. It matches the iOS 5 field. Proposed: darken to `#737376` (4.7:1), or accept it as a placeholder whose words are also the field's accessible name. |
| NPD-008 | Unresolved | Search popover secondary line `--srch-soft` on `--srch-bg` measures 2.6:1 light (4.8:1 dark). Sampled from iTunes 11. Proposed: `#6f6f6f` (4.8:1). |
| NPD-009 | Unresolved | White text on the iTunes 10 selection gradient measures 3.4:1 at the lightest stop (`--lib-sel-top`) and 5.1:1 at the darkest. Rows are bold 11px, so 4.5:1 applies. Proposed: shift the top stop to `#4274c9` (4.6:1), keeping the gradient's direction. |
| NPD-010 | Unresolved | White on the contextual menu highlight measures 3.2:1 at the top stop (`--ctx-hi-top`). Same trade-off as NPD-009; proposed top stop `#3a73d8` (4.5:1). |
| NPD-011 | Unresolved | Preferences selection `--prefs-sel` with white measures 4.0:1 in light. Proposed: `#316fcb` (4.9:1). |
| NPD-012 | Adopted    | Disabled menu items (`--ctx-ink-off`) are exempt from the text-contrast target (WCAG 1.4.3 excludes inactive components); they are measured and shown for information only. |
| NPD-013 | Adopted    | Rule IDs here use the NP- prefix and decisions NPD-, so they merge into AudioWave's `design/ux-rules.json` and `design/decisions.md` (UX-*, DEC-*) without collisions. |
| NPD-014 | Proposed   | When the header becomes AudioWave's player, map these families onto `packages/aqua-ui` components (status bar → PageBar, mode switch → ModeSwitch, scrubber/transport → TrackScrubber/KeyTransport, equalizer → the `.eqw` window) and retire duplicated values in favour of that repo's tokens. |
| NPD-015 | Adopted    | 316 raw colour literals remain outside the token blocks, recorded per section in `design/raw-colour-baseline.json`. Most are white/black alpha for lips, embosses and shadows, which are part of each material. The QuickTime controller bar (97) came in as a separate player and was not tokenised. The check fails if any section gains a literal; new colours are tokens. |
| NPD-016 | Adopted    | The Discover design (airwave-discover-1.html) puts **Revert** and **Apply** in the footer and says the engine "is rebuilt nightly at 3:00 AM". Revert is adopted: it restores every setting to when Settings opened. Apply is not: settings take effect as they change (NP-PREF-002), so Apply would be a button that does nothing (NP-PRIN-001). The nightly-rebuild line is not adopted either — no engine runs in this page to rebuild. When the engine lives in the AudioWave container, "Apply" becomes "Send to the engine" and this decision is revisited. |
| NPD-017 | Adopted    | The design's figures are sample numbers. Here every chart reads the device's own logs (NP-PRIN-003): genre and release-year charts show where their data will come from (the companion app) until tracks carry it, and "how each genre went" is drawn per artist until genres exist. |
| NPD-018 | Adopted    | Plays logged before the transport timed tracks have no seconds. They count as plays but are left out of every "heard" measure (played to the end, skipped, completion per song), and the table shows how many plays were timed. |
| NPD-019 | Adopted    | The familiarity tiers and the "new to you" series use one blue ramp (--viz-t1…t4, --viz-lo), validated as an ordinal ramp in both themes on the well and the panel: monotone lightness, visible steps, light end ≥ 2:1. The lighter steps sit under 3:1, so every tier and series carries its value in text beside it. |
| NPD-020 | Adopted    | Mode names follow the design: For you, Similar sounds (the engine's `playlist` mode), Genre, Similar, Deep cuts, New releases, Recent. Each mode's sentence says what it multiplies, which is what tells "Similar sounds" and "Similar" apart. |
| NPD-021 | Adopted    | Settings' pop-ups and checkboxes are Mac OS X 10.4 Aqua controls, from the Aqua Controls reference the owner supplied; its push buttons are Snow Leopard's (10.6) instead — a matte, brushed-metal pill with a graphite hairline that turns blue when pressed — because the owner found the 10.4 gel pill too glossy. The default button is 10.6 blue. AquaArt draws them as SVG from colour profiles sampled row by row from that reference and hands them to CSS as border-image sources, so the 22 sampled rows of each material stay together in one constant rather than becoming tokens; only the label ink and focus ring are tokens (--prefs-aqua-*). These are physical materials, so they keep their daylight drawing and black label in the dark theme. The equalizer keeps its brushed-metal controls, and the back button its iPhone OS cap. |
| NPD-022 | Adopted    | Connections live in Sources, not Player, because they are where the sources come from. The two tests call the endpoints the AudioWave repo defines — the companion's local helper at /helper/v1/health on 127.0.0.1:17342 (probing the three ports above, as the helper does) and the Docker hub's /healthz, /readyz and /api/v1/hub on 4546 — rather than the invented /health this page used to call. What's passed says "Ready" only once the destination has answered; it never claims a transfer it hasn't seen. Channel playlists and the programme guide go to the container, as the companion app's Live TV tab already says. |
| NPD-023 | Adopted    | Statistics is the owner's airwave-statistics.html page, ported into the Settings pane: its data, three.js views and page scripts as they were, its CSS scoped to #pp-stats with every colour a token (new --viz-g1…g7, --viz-sky-0, --viz-peak, --viz-hot, --viz-link, --stat-*), and dark values added. three.js comes from the existing import map (moved to the top of <head> so no early import can disable it), not the 580 KB copy bundled in the file. The player's history — with the library's titles, artists and tempo, and NPD-018's untimed plays — is the default source; a labelled demo year shows only while nothing has been recorded (an exception to NP-PRIN-003). The recommendation funnel (NP-DATA-003) was kept in Sources & sessions; the old tiles' taste-confidence line and release-year and new-vs-familiar charts were not part of the design and are gone. In this repo the generated demo year is gone (DEC-019): Statistics shows this player's recorded history, and an empty history is an empty year. |
| NPD-024 | Adopted    | Backup lives in Sources, next to the folders it copies. The player can't move files, so media backups are a request to the companion app, which does the copying between your folders and the container (its hash-checked, resumable transfers) and shows progress in its Transfers view. Neither the companion's local helper nor the hub in the AudioWave repo has a backup-request endpoint yet: the page records and logs the request, and says "requested", never "backed up". In this repo the companion runs real backups (Step B, DEC-018) and the player measures with the same code; Back Up Now in the player says nothing was sent. |
| NPD-025 | Adopted    | Profiles are the container's, not the browser's: the player pairs with the hub through its existing pairing routes and keeps only the device credential (in its own store, outside the settings Revert covers). The profile routes it calls are specified in docs/hub-profiles.md — the hub doesn't have them yet — including case-insensitive unique usernames enforced by a unique index. A shared playlist is CSV (title, artist, album, seconds) so it reads anywhere; another person's song plays only if the same title and artist are in your library. On Music, your picture takes the jewel case's place, as a round portrait. In this repo the profile routes exist (Phase 1A) and the shell calls them. |
| NPD-026 | Adopted    | The default volume lives in the Equalizer pane, next to the other things about how Airwave sounds. It is one level for every source: the video player now starts at and follows the bar's volume instead of keeping its own. |
| NPD-027 | Adopted    | The demo scaffolding under the player (main.demo, NPD-006) is gone: the file is the product now, not a header prototype with notes beneath it. The "body" type role points at the Settings lead paragraph instead. |
| NPD-028 | Adopted    | The backup's expected size and each destination's free space (NP-PREF-011) are measured where the data is: the player sizes playlists, settings and algorithms exactly (it holds them); the companion measures the media folders and its backup drive, the container its backup directory. Neither route exists yet — docs/backup-space.md specifies both (`GET /helper/v1/backup/estimate`, `GET /api/v1/backup/space`) — so until they answer the page says which figure is waiting and who will supply it, and never shows a guess. Sizes are decimal, as the Finder has counted since Snow Leopard. Helper calls now carry the run's token from the page the helper serves (HELPER_TOKEN_META). In this repo both routes exist (Phase 1C): GET /helper/v1/backup/estimate and GET /api/v1/backup/space. |
| NPD-029 | Adopted    | While Settings covers the player on Music or Radio, the header's search pill gives way to a mini player (NP-CHROME-003), because Settings hides the transport and search has nothing to search there. Video is different: a film or episode left behind pauses, and Live TV is disconnected rather than muted, so a stream isn't kept open for a picture nobody is watching. Skip in the mini player (and the transport's Next on Music) moves to the next song in the list's order. |
| NPD-030 | Adopted    | Several songs are picked the Finder's way — a rubber band dragged across empty space, Cmd/Ctrl-click, Shift-click (NP-LIST-003) — and act together through one menu whose commands name the count (NP-MENU-004). A single click still plays, as it always has here, so the drag starts only after 5 px and the click that ends it is swallowed. The band is two-tone (--lib-marquee-*) so it reads over the blue selection. Touch keeps long-press for one song; multi-select on touch is not offered. |
| NPD-031 | Adopted    | Groups and invites use the hub's real group routes (create, invite code, join, leave). The hub has no way yet to preview a code, address an invite to a person, record a decline, or list and withdraw codes — docs/hub-group-invites.md specifies them. The player tries each and falls back without pretending: the invite page labels the group name as the link's until the container confirms it, a sent link offers Remove (with a note that the code keeps working) instead of Withdraw, a decline is kept on the device, and inviting someone from their profile copies the link for you to send when the container can't deliver it. An invite link's details live in the URL fragment, which no server receives, and the page removes it from the address bar once read. In this repo the invite routes exist (Phase 1B): list, withdraw, preview, /me/invites, accept, decline. |
