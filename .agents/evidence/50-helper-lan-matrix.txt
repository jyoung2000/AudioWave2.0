NOTES, so the report is not read as more than it is

1. /helper/v1/health answers with no Origin while /tv/channels and /radio/now-playing do not. That is
   deliberate and commented in the source, not an inconsistency:

     - local-helper/src/server.ts:203-207 refuses radio/now-playing with no Origin and no token
       precisely so the helper cannot be used as a blind GET relay by any website's <img>.
     - handleLan (server.ts:171) only vets the Origin when one is present; health carries no data a
       stranger should not have and is the route that answers "is a helper here at all".

   So on the network: health is a bare reachability probe, and the two content routes need a page
   served from this network. That matches the wording of the toggle's own hint text.

2. A Windows Firewall prompt appears the first time the helper binds 0.0.0.0. The owner answered it
   ("Private networks" only). That is a person, not an automated step.

3. NO SECOND PHYSICAL DEVICE WAS AVAILABLE on this network. Every request above was issued from this
   same PC, but over its LAN address and with the LAN Host/Origin rules in force -- so the helper's
   network-side decisions are proven; what is NOT proven is that a phone or another PC can reach it,
   which depends on the firewall rule the owner allowed and on that device's own network.
