# Catalog provider research

Checked 2026-10-14 while improving artist search in Airwave. The shared implementation point is already in-repo: [`packages/domain/src/catalog/`](../packages/domain/src/catalog/) provides the provider interface and merge engine; the player selects the paired Hub, then the PC's local helper, then its browser engine in [`music-player/src/shell/search/client.ts`](../music-player/src/shell/search/client.ts).

## Findings and integration constraints

- **YouTube Music:** I found no official YouTube Music catalog API in Google's documented YouTube Data API. Its [`search.list`](https://developers.google.com/youtube/v3/docs/search/list) returns video, channel, and playlist resources, not canonical music-artist discographies. Do not label generic video search as a YouTube Music catalog or use undocumented internal endpoints as trusted artist data.
- **Spotify:** The official Web API supports search and artist/album detail; browser clients can use [Authorization Code with PKCE](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow). But the [Spotify Developer Policy, section III.5](https://developer.spotify.com/policy#iii-some-prohibited-applications) says not to create a product “integrated with streams or content from another service.” Airwave is a multi-provider player, so a Spotify metadata adapter merged into its other-provider catalog needs explicit Spotify permission. Do not add one absent that permission.
- **Apple Music:** The keyless [iTunes Search/Lookup API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/) is available as the browser fallback, but is not the full Apple Music catalog. The official [Apple Music API search endpoint](https://developer.apple.com/documentation/applemusicapi/search-for-catalog-resources-(by-type)) needs a developer token; [token generation](https://developer.apple.com/documentation/applemusicapi/generating-developer-tokens) uses a developer signing key, which must remain server-side. A Hub is not required, but token provisioning/rotation is.
- **SoundCloud:** The [official API guide](https://developers.soundcloud.com/docs/api/guide) documents public search with Client Credentials and states that clients are currently confidential, so obtaining a token requires a client secret. That secret cannot safely ship in the PWA; use a separately operated token broker if adding the official API without the Hub.
- **YouTube / SoundCloud / Spotify without the Hub:** Airwave already has a no-Hub route through its independent [`local-helper`](../local-helper/), which runs `yt-dlp` for YouTube/SoundCloud search and `spotDL`/public embeds for Spotify link metadata. The real-socket integration test is [`local-helper/tests/integration/helper-catalog.test.ts`](../local-helper/tests/integration/helper-catalog.test.ts). This requires the companion/local helper and its tools; it is not a browser-only integration, and Spotify text search is not implemented there.

## Repository candidate considered

[`vladdenisov/ytmusic-api`](https://github.com/vladdenisov/ytmusic-api) is an MIT-licensed, unofficial Node/TypeScript YouTube Music wrapper (GitHub reported its last update as 2026-06-25). Its [README](https://raw.githubusercontent.com/vladdenisov/ytmusic-api/master/README.md) describes Node usage and cookie-based authenticated calls. It is not an official or browser-first catalog contract, so it was not added as a dependency; the existing local helper already has a replaceable `yt-dlp` runner and does not require undocumented browser scraping.

## Implementation decision

Keep provider adapters behind the existing `CatalogProvider` interface. Preserve provider IDs rather than merging artists by display name: names such as “Drake” are not unique identities. Rank exact-name Deezer artist hits by the provider's fan count, and request up to one 100-album Deezer page plus 50 top tracks for an artist detail. Keep provider attribution and each source's own artist ID so the player does not silently redirect a selection to another same-named artist.
